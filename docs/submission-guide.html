Before a selector considers a future file

  1. Obtain an explicit single-method assignment and preregister the hypothesis before fitting. Reuse shared components; perform per-feature canaries, buffered whole-segment hide-and-recover holdout, and a paired same-run comparison.
  2. Check absolute full-footprint rank correlation against every declared reference before dot placement and on the final file; stop for |ρ| > 0.90 or >70% of candidate dots within 3 pixels of any reference. Missing, misaligned or unavailable references are unverified, not a pass. Do not waive dense references.
  3. Independently re-read the exact TIFF and verify SHA-256, one float32 band, the pinned template's CRS/shape/transform, finite [0,1] values inside the footprint, and the exact known-fault mask. The local promotion policy also requires all array values to pass strict [0,1]; this conservative check does not establish the organizer's padding requirements.
  4. Run python scripts/verify_candidate_independent.py path/to/candidate.tif. If proposing a ZIP, add --require-zip and verify that it contains exactly the audited TIFF bytes. Run python scripts/check_readiness.py evidence.json --output decision.json for receipt consistency; see the receipt schema and evidence requirements. A pass permits selector review only and does not authenticate the evidence or authorize a slot.
  5. A separate owner selector must choose a candidate and authorize any weekly slot. Only then follow the current organizer instructions manually, checking the file hash and retaining any receipt. This repository does not automatically access the organizer or upload.

Portal warning: the reported “Predicted values must be in range [0, 1]” is consistent with NaNs inside an earlier owner-mirrored footprint, but the actual cause is not proven. Outside-footprint NaN and zero conventions have not been organizer-confirmed here; neither an all-finite file nor a ZIP proves portal acceptance.
