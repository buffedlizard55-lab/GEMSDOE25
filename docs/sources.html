IDLevelIssue · evidence · action
IR-25-NAN-FOOTPRINTcriticalfixedThe first GEMSDOE25 'recommended' submission (gems25-factorial-best-v1-nan.tif, sha256 fbef100f...) used an invented footprint: 2,344,929 of the 5,167,373 official in-footprint pixels are NaN and 2,832,257 pixels outside the footprint are finite. NaN fails every 0<=x<=1 test, which explains the portal message 'Predicted values must be in range [0, 1]'.
Evidence: evidence/old_gems25_tif_forensics.json (recomputed from git history, commit 9b01f27, against the pinned organizer template)
Action: File removed. src/gems25/submission.py takes the footprint from the template raster, refuses NaN inside it, and check_file() reproduces the failure (tests/test_submission.py). Cause is *inferred from the data*, not confirmed by DrivenData; the portal's own validator is not public.
IR-25-OVER-EMISSIONcriticalfixedThe same file emitted 1,249,834 positive pixels (624,029 inside the footprint = 12.1 % of it; 625,805 outside it), roughly 10x the 2.34 % budget of H19-5 and 21x the dotted file's 60,069 pixels. At the measured truth density the false-positive term would swamp the score. The old site nevertheless said 'FORMAT VERIFIED' and the README credited the dot-thinning of the 0.2477 file.
Evidence: evidence/old_gems25_tif_forensics.json; evidence/why_0_2477.json
Action: Replaced by files whose emission is justified by the metric algebra and the hide-and-recover results.
IR-25-FAKE-PIPELINEhighfixedPrevious scripts were non-functional or misleading: generate_submission.py wrote synthetic diagonal stripes inside an elliptical made-up footprint; ridge_detector.py was a toy; factorial_design.py never ran (no data); the README listed src/feature_families.py, src/emission_policies.py and reference_solution/ that did not exist; the page's 'Footprint all finite / All checks pass' described a file that failed them.
Evidence: git show 9b01f27 (scripts/, README.md, docs/index.html)
Action: Removed from the working tree (kept in history). Replaced by tested modules under src/gems25 and executed experiments.
IR-25-DTI-KERNELhighfixedThe old scripts/dti_metric.py used kernel 1 - d/(R+0.5) with R = 3 px (support 3.5 px). The official kernel is max(1 - d/R, 0) with R = 300 m = 3 px.
Evidence: scripts/dti_metric.py @ 9b01f27 vs https://www.drivendata.org/competitions/306/competition-doe-gems/page/967/
Action: src/gems25/metric.py implements the published equations; tests compare it with a brute-force transcription.
IR-25-TC-BANDhighflaggedBand 6 'tc' of the mirrored training_features.tif is described as 'Tilt angle or total curvature - magnetic field derivative for edge detection', but its values (3.7-70.6, positive) equal the official GeoDAWN radiometric total count channel: Spearman 0.9999 against the USGS-release TC grid (and 0.89/0.91/0.72 with K/Th/U).
Evidence: evidence/band_semantics.json (computed)
Action: Band treated as radiometric TC and placed in family D (geochemical). The embedded description is wrong; do not rely on other descriptions without checking.
IR-25-BAND-ALIASESmediumopenOther band descriptions disagree with the organizers' page: 'deq_n100a15' = 'Distance to earthquake' vs official 'Density of earthquakes' (and two earthquake bands vs one official layer); 'depth_to_base_surf' = 'Depth to basement surface' vs official 'depth to conductive base surface'; no band is named as the 'top-of-crustal magnetic source depth estimate' (mag_anom is an nT anomaly).
Evidence: registry/data_manifest.json; https://www.drivendata.org/competitions/306/competition-doe-gems/page/967/
