Why the portal said "Predicted values must be in range [0, 1]"

  • NaN fails every 0 <= x <= 1 test. A NaN-outside GeoTIFF therefore fails a whole-array range check.
  • The official reference solution writes its output as a finite float raster with no NaN and no nodata tag (verified in unet-mc-cv-reference-solution.ipynb at pinned commit aebe92f).
  • The owner-mirror sample_submission.tif uses NaN outside its 5,167,373-pixel footprint, which conflicts with the portal's rejection of NaN. This is flagged for owner review; it is not resolved by any organizer receipt.
  • The fix in this repository: the validator now requires every cell to be finite and in [0, 1] (portal_all_cells_finite_in_0_1). Use the -zeros.tif file if a file is ever cleared.

How GEMSDOE32 reached 0.2778 (verified receipts; mechanism is an inference)

  • The file is binary: 37,654 dots at value 1.0; zeros elsewhere; 0 dots on the labelled catalogue.
  • Nested lineage (set inclusion verified on the pinned rasters): GEMSDOE32 B2 (37,654 dots, 0.2778) ⊂ GEMSDOE28 h27-4-r1-solo (40,199, 0.2708) ⊂ GEMSDOE25 d2-8 (44,090, 0.2600). Only dots were deleted at each step: 3,891 dots, then 2,545 dots.
  • What was deleted: all 6,436 removed dots lie 1 to 2 pixels (about 100–200 m) from a labelled catalogue pixel. B2 keeps zero dots within 2 px of the catalogue; d2-8 had 6,436 such dots. The owner-reported score rose 0.2600 → 0.2708 → 0.2778 across these two deletions.
  • Mechanism is contested, not settled. The repository's record of the staff clarification (knowledge/03; not re-fetched here, because AGENTS.md rule 3 bars automated access to drivendata.org forums) says near-known wrong pixels are fully penalised. That favours deletion. The same record says test labels include corrections or modifications within 300 m of known traces. That favours keeping them. The catalogue-gap holdout cannot test this (IR-25-HOLDOUT-DOES-NOT-TEST-PRUNING, knowledge/17 §2), so the question is open.
  • B2 is already widely submitted (owner-reported): two re-hosts carry the same SHA prefix c55bafc4 and score 0.2778 (GEMSDOE50, GEMSDOE58), and 15 B2 micro-variants score 0.2720–0.2775 (evidence/b2_microvariants.json, all below B2). A copy of B2 is therefore a previous submission on several sites.
  • Lane consequence (arithmetic): B2 is a registry reference in the H75 lane receipt (docs/downloads/lane-gems25-h75-dchb-cg-catfree-b2-37654-20261027-e035d75ca5d5-zeros.json, entry g32_h33-2-b2_0.2778.tif). Any subset of B2 has 100% of its dots within 3 px of B2 itself, so further pruning of B2 is a literal lane duplicate. Escaping the lane needs dots moved away from the B2 family, which is a different (untested) science question.
  • Within-family similarity: the nine focus tops are near-duplicates of one another (max Jaccard in the table). The leaderboard-level differences are differences within one dot family, not a new geological discovery.
