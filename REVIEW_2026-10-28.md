## 3. Official reference solution — what the format really is

Source: `drivendataorg/gems-prize-reference-solution`, `unet-mc-cv-reference-solution.ipynb`, cell 19 (read from the repository tarball at `https://codeload.github.com/drivendataorg/gems-prize-reference-solution/tar.gz/refs/heads/main`; repo page: https://github.com/drivendataorg/gems-prize-reference-solution).

- The reference writes `dtype=y_final.dtype` (float32 model output), `count=1`, with the CRS and transform of the labels raster.
- It sets **no nodata tag** and does not write NaN.
- Therefore a NaN-outside file is **not** the reference's format. The portal error "Predicted values must be in range [0, 1]" matches the NaN case the repo already logged as `IR-25-NAN-FOOTPRINT` (fixed, but the NaN file is still the front-page default in some places).

**Flag for owner review:** the README front-page still links NaN-outside files as the primary downloads, while the reference solution writes finite output everywhere. Until DrivenData confirms the accepted convention with a submission-page receipt, the zeros-outside variant is the closer match to the reference, and that is still unconfirmed by the organizer.
